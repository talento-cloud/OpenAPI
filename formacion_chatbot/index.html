Microservicio para gestión en talento cloud del módulo de Formación, pensado para ser consultado por chatbot ClaudIA.

Manejo de errores

Los errores habituales pueden incluir:

- `400 Bad Request`: Parámetros requeridos faltantes o con formato
inválido.

- `401 Unauthorized`: Token JWT inválido, expirado o ausente.

- `403 Forbidden`: El usuario autenticado no tiene permisos suficientes.

- `404 Not Found`: El recurso solicitado no existe.

- `500 Internal Server Error`: Error inesperado en el servidor.


Cuando sea posible, cada endpoint detallará sus códigos de error
específicos y estructura de respuesta en su propia descripción.

Formacion

temasPorAnio

Lista los temas de formación programados que el usuario autenticado (identificado por el token de sesión, nunca por parámetro) tiene asignados para un año determinado. Solo lectura: no crea, modifica ni elimina información.

Visibilidad: un tema aparece únicamente si el usuario tiene fila activa en frm_plan (usuario, tema, año) y en frm_usuario_tema (usuario, tema) — es decir, solo se listan los temas propios del usuario en sesión, nunca los de otro usuario.

El campo fecha de cada tema es el rango mesInicial/mesFinal del año de formación consultado (frm_anio), en formato YYYY-MM-DD/YYYY-MM-DD; es el mismo valor para todos los temas de un mismo año.

Si el año consultado no tiene temas (o no existe como año de formación activo), la respuesta es 200 OK con data.temas vacío y un message explicativo — la ausencia de temas no es un error.

Authorizations:
bearer
query Parameters
anio
string
Example: anio=2026

Nombre del año de formación a consultar (frm_anio.nombre) — no es necesariamente un número de 4 dígitos: puede ser texto libre como "Plan Aprendizaje 2025" o "Otras formaciones 2026", según cómo lo haya configurado cada cliente. La comparación es insensible a mayúsculas/minúsculas y a tildes ("formación 2026", "FORMACION 2026" y "Formacion 2026" resuelven igual). Si no se envía, se usa el año de formación activo más reciente (el de código más alto entre los frm_anio activos) — no se asume que ese año se llame igual que el año calendario actual, ya que no siempre es así. No se valida ningún formato particular — si el valor enviado no coincide con ningún año de formación activo, la respuesta es 200 OK con data.temas vacío, no un error.

temasPendientes

Lista los temas de formación pendientes del usuario autenticado (identificado por el token de sesión, nunca por parámetro) para un año determinado. Solo lectura.

Un tema se considera pendiente cuando: (1) está asignado al usuario (frm_plan + frm_usuario_tema activos), (2) no ha completado todas sus acciones (chuleado=true en frm_acciones_usuario para cada frm_acciones_tema del tema — completado equivale a aprobado, no hay umbral de nota separado), y (3) el año de formación consultado sigue vigente (frm_anio.mes_final >= hoy).

evaluacionPendiente indica si, entre las acciones sin completar del tema, hay al menos una marcada como evaluación (frm_acciones_tema.es_evaluacion=true).

fechaLimite = fecha de asignación del tema al usuario (frm_plan.creado) + frm_tema.tiempo_limite días; null si el tema no tiene tiempo límite configurado.

Si no hay pendientes (o el año consultado ya no está vigente), la respuesta es 200 OK con data.temas vacío y un message explicativo — no es un error.

notaGeneralTema

Retorna la nota general (consolidada) del usuario autenticado (identificado por el token de sesión, nunca por parámetro) en un tema de formación puntual, y si aplica su estado aprobado/reprobado. Solo lectura.

¿Cómo se obtiene la nota? Cuando el usuario presenta la evaluación de un tema, el sistema guarda ese resultado. Si más adelante tiene una segunda oportunidad (un "refuerzo"), el sistema guarda también ese segundo resultado. La nota que entrega este endpoint es la mejor de las dos: si el refuerzo es más alto, se usa el refuerzo; si no, se usa la nota original. Cada vez que el usuario vuelve a presentar la evaluación general de ese mismo tema (por ejemplo, en un año posterior), el sistema reemplaza cuál es la nota "vigente" del tema — el resultado anterior queda en el historial, pero deja de ser la nota que se muestra. En otras palabras: el sistema recuerda de forma activa solo la nota del intento más reciente de cada tema, no el historial completo año por año.

El tema se identifica únicamente por nombre exacto (frm_tema.nombre, sensible a mayúsculas/tildes — sin normalización, mismo comportamiento que el resto de endpoints del chatbot que buscan por nombre); no se admite búsqueda por id.

La nota consolidada es la del registro de evaluación general del usuario en el tema (frm_usuario_tema.evaluacion → frm_evaluacion, la evaluación sin acción asociada): se toma refuerzo si existe, es mayor a 0 y no es inferior a evaluacion; en caso contrario se toma evaluacion. Escala 0-5.

aprobado compara esa nota contra la propiedad de tenant FRM_NOTA_ESPERADA (el mismo umbral configurable que usa el cuadro de mando de Formación). Si el tenant no tiene esa propiedad configurada, aprobado se retorna null en vez de asumir un umbral por defecto.

anio es opcional y se resuelve con el mismo criterio que /temas (año de formación activo más reciente si no se envía). No determina cuál nota se devuelve — la nota entregada siempre es la más reciente que el sistema tiene registrada para el tema, sin importar el año exacto en que se presentó el intento. Esto se verificó directamente contra la base de datos, no es un supuesto: el sistema sí guarda el año en las evaluaciones de una actividad puntual y repetible dentro de un tema, pero nunca lo guarda en la evaluación general del tema completo (0% de los casos revisados, en los tres ambientes de prueba disponibles). Tampoco es viable deducir el año a partir de la fecha en que se presentó la evaluación: al revisar los casos reales, alrededor de 1 de cada 5 quedaría sin año asociado porque su fecha no cae dentro de ningún año de formación configurado como vigente en ese momento.

En cambio, anio sí determina si el endpoint responde o no con datos: se usa para confirmar que el tema está en el plan de formación del usuario para ese año (esto sí se conserva correctamente año por año, a diferencia de la nota). Si el tema no estaba en el plan del usuario para el año consultado, la respuesta es 404 Not Found — igual que si el tema no existiera — aunque el usuario tenga una nota general de ese tema registrada en otro año. Si el tema sí estaba en el plan de ese año, se pasa a la siguiente validación.

La nota no se considera definitiva si el tema no está terminado. Un tema se compone de varias acciones (contenidos, actividades, la evaluación, etc.); es posible que el usuario ya haya presentado la evaluación general (y por lo tanto tenga una nota guardada) sin haber completado todavía el resto de esas acciones para el año consultado. Si el usuario no ha completado todas las acciones del tema ese año, el endpoint responde igual que si no tuviera nota registrada, aunque exista un valor de evaluación guardado. Esta validación reutiliza exactamente el mismo criterio que ya usa /temas/pendientes para decidir si un tema cuenta como terminado (acciones completadas/"chuleadas" por el usuario ese año, contra el total de acciones del tema) — a diferencia de la nota, esto sí se conserva correctamente año por año.

Si el usuario no tiene una nota registrada para el tema (no existe evaluación general asociada, esta no tiene valores de evaluacion/refuerzo, o el usuario aún no completó todas las acciones del tema ese año), la respuesta es 200 OK con data.tieneNota=false, data.nota=null, data.aprobado=null y un message explicativo — no es un error. El endpoint no distingue en la respuesta cuál de esos motivos aplicó.

Si el tema no existe, no está asignado al usuario, o no estaba en su plan de formación para el año consultado, la respuesta es 404 Not Found con success=false.
