API publica de talento cloud (1.0)

Download OpenAPI specification:

API REST para entregar info a clientes y proveedores.

En la documentación se mencionan 2 urls:

  • Producción: https://[tenant].talento.cloud/
  • Pruebas: https://[tenant].talento-dev.cloud/

El client_id y client_secret son suministrados por talento cloud al cliente.

La IP del cliente debe estar en la lista blanca de IPs permitidas para tener acceso a estas APIs. El cliente debe suministrar su IP publica para registrarla en dicha lista.

Maneja autenticación Oauth 2.0 y se podria consultar diferentes endpoints en formato application/json

Manejo de errores

Los errores habituales pueden incluir:

- `400 Bad Request`: Parámetros requeridos faltantes o con formato
inválido.
    
- `401 Unauthorized`: Token JWT inválido, expirado o ausente.
    
- `403 Forbidden`: El usuario autenticado no tiene permisos suficientes.
    
- `404 Not Found`: El recurso solicitado no existe.
    
- `500 Internal Server Error`: Error inesperado en el servidor.
    

Cuando sea posible, cada endpoint detallará sus códigos de error
específicos y estructura de respuesta en su propia descripción.

Autenticación

Endpoints para autenticación y obtención de tokens de acceso OAuth 2.0.

OAuth2 - Obtener token

Para obtener el token que autoriza uso de los otros servicios, el client_id y client_secret son suministrados por talento cloud al cliente, según el tenant la url cambia, por ejemplo para la empresa ClienteX sería https://clientex.talento.cloud/html/oauth2/token/clientex.json

Ejemplo petición con curl:

curl -X POST https://clientex.talento.cloud/html/oauth2/token/clientex.json \
  -H "Content-Type: application/x-www-form-urlencoded" \          
  -d "grant_type=client_credentials" \
  -d "client_id=webhook-servicio" \
  -d "client_secret=mi-secreto" \
  -d "scope=talento.hojavida.read"

Ejemplo uso token generado:

curl -X POST https://clientex.talento.cloud/html/v1/public/hojavida/informe/informacionNomina.json?start=0&limit=100  \
  -H "Authorization: Bearer eyJhbGci..."

Transversal - Carga masiva de usuarios a partir de un arreglo JSON

Recibe un listado de usuarios en formato JSON y realiza su creación o actualización masiva en el sistema.

Procesamiento asíncrono. La respuesta 202 confirma que la solicitud fue recibida e inició el procesamiento; no indica que la carga haya terminado ni que todos los registros sean válidos. El resultado final (cargas exitosas, advertencias y errores) se envía por correo electrónico al usuario asociado al cliente API y a los destinatarios configurados para el cliente.

Una carga a la vez. Solo se procesa una carga por cliente en cada momento. Si hay otra en curso, el servicio responde 409 y la solicitud no se procesa; reintente cuando la anterior haya finalizado.

Requisitos. El token debe incluir el permiso talento.usuarios.write y pertenecer a un cliente API habilitado para la carga de usuarios; de lo contrario se responde 403.

Errores por registro. Los errores de validación de cada registro no se retornan en la respuesta HTTP; se informan en el correo con el resultado de la carga.
