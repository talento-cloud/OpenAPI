Datalake - API publica de talento cloud (1.0)

Download OpenAPI specification:

API REST para entregar info a datalake.

En la documentación se mencionan 2 urls:

  • Producción: https://[tenant].talento.cloud/
  • Pruebas: https://[tenant].talento-dev.cloud/

El client_id y client_secret son suministrados por talento cloud al cliente.

Maneja autenticación Oauth 2.0 y se podria consultar los siguientes informes en formato application/json:

  • HojaVida - Información de nómina - OK
  • HojaVida - Reporte datos básicos usuario interno - Pendiente
  • Selección - Reporte de selección detallado - Pendiente
  • Selección - Seguimiento por etapas - Pendiente
  • Formación - Avance por tema - Pendiente
  • Bienestar - reporte detallado beneficios/reconocimientos - Pendiente
  • Bienestar - reporte transacciones puntos beneficios/reconocimientos - Pendiente
  • Objetivos Smart - Resultados consolidados de gestión (Todo el grupo) - Pendiente
  • Objetivos Smart - Modelo mapa de desempeño - Pendiente
  • Competencias - Detalle valoración de competencias (de todo el grupo) - Pendiente
  • Operativos (Dec) - Reporte operativos - Pendiente
  • Transversal - Reporte de todos los usuarios del sistema - OK
  • Transversal - Reporte de los usuarios activos - Pendiente
  • Transversal - Novedades - Pendiente

Manejo de errores

Los errores habituales pueden incluir:

- `400 Bad Request`: Parámetros requeridos faltantes o con formato
inválido.
    
- `401 Unauthorized`: Token JWT inválido, expirado o ausente.
    
- `403 Forbidden`: El usuario autenticado no tiene permisos suficientes.
    
- `404 Not Found`: El recurso solicitado no existe.
    
- `500 Internal Server Error`: Error inesperado en el servidor.
    

Cuando sea posible, cada endpoint detallará sus códigos de error
específicos y estructura de respuesta en su propia descripción.

OAuth2 - Obtener token

Para obtener el token que autoriza uso de los otros servicios, el client_id y client_secret son suministrados por talento cloud al cliente, según el tenant la url cambia, por ejemplo para la empresa Alianza sería https://somostalentoalianza.talento.cloud/api/html/oauth2/token/somostalentoalianza.json

Ejemplo petición con curl:

curl -X POST https://somostalentoalianza.talento.cloud/api/html/oauth2/token/somostalentoalianza.json \
  -H "Content-Type: application/x-www-form-urlencoded" \          
  -d "grant_type=client_credentials" \
  -d "client_id=webhook-servicio" \
  -d "client_secret=mi-secreto" \
  -d "scope=talento.read"

Ejemplo uso token generado:

curl -X POST https://somostalentoalianza.talento.cloud/api/v1/datalake/modulox/reportey  \
  -H "Authorization: Bearer eyJhbGci..."

Transversal - Reporte de todos los usuarios del sistema

Endpoint donde se lista la información de todos los usuarios del sistema para Datalake. Permite filtrar por tipo de usuario (Todos, Administrativo u Operativo). Las fechas se entregan en formato yyyy-mm-dd.

Authorizations:
oauth2
path Parameters
tipo_usuario
required
string
Enum: "Todos" "Administrativo" "Operativo"
Example: Todos

Tipo de usuario a consultar (Todos, Administrativo u Operativo).

header Parameters
Accept-Language
string
Example: es

Idioma de las alertas de error (por ejemplo 'es').

Responses

Servidor de producción

https://somostalentoalianza.talento.cloud/api/html/v1/datalake/transversal/todosUsuarios/{tipo_usuario}.json

Servidor de pruebas

https://somostalentoalianza.talento-dev.cloud/api/html/v1/datalake/transversal/todosUsuarios/{tipo_usuario}.json

Request samples

  • cURL
curl --location 'https://somostalentoalianza.talento-dev.cloud/api/html/v1/datalake/transversal/todosUsuarios/Todos.json' \
  --header 'Accept-Language: es' \
  --header 'Authorization: Bearer <TU_TOKEN_JWT>'
