API Analíticas - Selección (PowerBI) (1.0)

Download OpenAPI specification:

Esta API permite acceder a la información analítica del módulo de Selección (procesos de requisición, candidatos, etapas, encuestas de satisfacción y maestros de apoyo) de una empresa, consumida por PowerBI para la construcción de reportes analíticos.

Manejo de errores

Los errores habituales pueden incluir:

- `400 Bad Request`: Parámetros requeridos faltantes o con formato
inválido.

- `401 Unauthorized`: Token JWT inválido, expirado o ausente.

- `403 Forbidden`: El usuario autenticado no tiene permisos suficientes.

- `404 Not Found`: El recurso solicitado no existe.

- `500 Internal Server Error`: Error inesperado en el servidor.


Cuando sea posible, cada endpoint detallará sus códigos de error
específicos y estructura de respuesta en su propia descripción.

## Autenticación

Estos servicios están pensados para ser consumidos por PowerBI y se
protegen con autenticación básica HTTP (usuario y contraseña), las
cuales son provistas por talento cloud para la integración.

Seleccion

informacionProcesos

Retorna la información detallada de los procesos de requisición de selección: datos generales (fechas, estado, vacantes, salario, duración), clasificadores organizacionales (cargo, área, negocio, empresa, UEN, vicepresidencia, sede), responsables del proceso, idioma/nivel requerido y el tiempo transcurrido calculado según el calendario laboral configurado. Pensado para ser consumido como fuente de datos de PowerBI.

Authorizations:
basicAuth

informacionAns

Retorna el Acuerdo de Nivel de Servicio (ANS, en días) calculado para cada cargo, según la configuración general de origen del ANS (trv_configuracion_general.origen_ans): puede tomarse del propio cargo, del nivel organizacional (tipo de cargo) o de la categoría del cargo. Pensado para ser consumido como fuente de datos de PowerBI.

Si no existen cargos configurados, el servicio retorna igualmente un arreglo con un único registro cuyos campos vienen vacíos (comportamiento explícito del backend, no es un error).

Authorizations:
basicAuth

Responses

informacionCandidatos

Retorna el listado de candidatos que participan en al menos un proceso de requisición activo, con su información básica y el número de procesos actuales y anteriores en los que ha participado. Pensado para ser consumido como fuente de datos de PowerBI.

Si no existen candidatos en procesos activos, el servicio retorna igualmente un arreglo con un único registro cuyos campos vienen vacíos (comportamiento explícito del backend, no es un error).

basicAuth

informacionCandidatosProcesos

Retorna el detalle del avance de cada candidato por cada etapa de los procesos de selección en los que participa: estado de la etapa, observaciones, motivo de descarte (si aplica), días que tomó el candidato en la etapa, días laborales y el cumplimiento de requisitos. Pensado para ser consumido como fuente de datos de PowerBI.

Si no existen etapas de candidatos registradas, el servicio retorna igualmente un arreglo con un único registro cuyos campos vienen vacíos (comportamiento explícito del backend, no es un error).

maestroAreas

Retorna el maestro de áreas, deduplicadas por nombre (normalizado con str_simple) dando prelación al registro activo cuando existen nombres repetidos. Pensado para ser consumido como fuente de datos de PowerBI (catálogo/dimensión de apoyo).

Si no existen áreas registradas, el servicio retorna igualmente un arreglo con un único registro cuyos campos vienen vacíos (comportamiento explícito del backend, no es un error).

basicAuth

informacionEtapasRequisicion

Retorna la información general de las etapas configuradas para cada proceso de requisición: orden de la etapa, fechas reales de inicio y fin (calculadas a partir de los candidatos que pasaron por la etapa), el ANS de la etapa y los días mínimo, máximo y promedio observados. Pensado para ser consumido como fuente de datos de PowerBI.

Si no existen etapas configuradas, el servicio retorna igualmente un arreglo con un único registro cuyos campos vienen vacíos (comportamiento explícito del backend, no es un error).
